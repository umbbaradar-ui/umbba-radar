## 3. 즉시 조치 (오늘)
1. Pro 전환(완료) → API 제한 해제 확인.
2. `tools/umbba-cli/storage_cleanup.py --delete-expired --days 14` : 고아 21,266 + 만료 14일+ 이미지 삭제 (≈1,180 MB → 잔여 ≈ 30 MB). 삭제 전 `--dry`로 목록·절감량 확인. 삭제 목록은 스크립트 출력으로 보관.
3. 만료 카드는 `thumbnail_url`을 비워 앱에서 깨진 이미지가 안 나오게 처리.
4. 남은 현역 이미지 250KB+ 재압축(`--recompress --max 1080`).

## 5. 플랜 운용
- Pro는 정리 완료·재발 방지 배포·용량 <300MB 확인 후 **다음 결제일(10/7) 전에 무료로 다운그레이드**. 다운그레이드 조건: 사용량이 무료 한도 이내.
- 단, 앱 사용자가 늘어 DB 500MB·대역폭 5GB(무료 한도)에 근접하면 Pro 유지가 맞다. 판단 지표는 E의 일일 집계로.

## 6. 운영 규칙 (이번 사고에서 배운 것)
1. **외부 저장소에 쓰는 자동화는 반드시 "삭제 경로"까지 설계한다.** 만들기만 하고 지우지 않는 잡은 언젠가 한도를 친다.
2. 무료 플랜 한도(Storage 1GB·DB 500MB·대역폭 5GB)는 **매일 잡이 숫자로 감시**하고, 50%에서 경보를 낸다.
3. 서비스 계정 키(service_role)는 맥 `~/umbba-radar/tools/umbba-cli/.env.storage`(gitignore) 한 곳에만. 대시보드 로그인은 은재.
4. 사고 대응 순서: **서비스 복구(플랜/한도) → 원인 데이터 확인 → 정리 → 재발 방지 코드 → 플랜 원복**. 정리부터 하다가 복구가 늦어지지 않게.
5. 관련 없는 최근 변경(어제의 영상 자동화)을 원인으로 의심할 땐 **월별 적재 분포**처럼 시계열로 검증한다.
