## 1. 사업의 정체성

### 확정된 것
- **유형:** 미디어 (큐레이션). 마켓플레이스·플랫폼 아님
- **차별점:** 외부 인스타·블로그 협찬을 **브랜드 중립적으로 모아 보여주는** 메타 큐레이션
- **수익 방식 우선순위:** 광고·노출비 → 공구 수수료 → 데이터·구독
- **운영 규모 가정:** 1인 개발자·운영. 자동화 가능한 부분 외엔 늘리지 않음

### 보류 (본인 결정 필요)
- **미디어 결:** 🅰 하이엔드 큐레이션 / 🅱 종합 정보 허브 / 🅲 커뮤니티 미디어 중 어느 결로 갈지 (수익 모델·큐레이션 기준이 달라짐)
- **타겟 페르소나 정밀화:** "임신중~초등 부모" 안에서 1차 타겟 1명 (예: "30대 초반 첫째 임신 7~9개월 직장맘")

## 2. 6-Layer 비즈니스 구조

```
Layer 1: 가치 명제
  "흩어진 육아 혜택을 한곳에 모아 놓치지 않게 한다"
        ↑
Layer 2: 핵심 자산 (Moats)
  큐레이션 DB · 사용자 행동 데이터 · 분류 체계 · 신뢰 · 브랜드 관계망
        ↑
Layer 3: 핵심 기능 부서 (도메인 코어 — 사업의 심장)
  Content · Brand · User · Personalization · Curation · Discovery
        ↑
Layer 4: 운영 부서 (성장·유지)
  Ingestion · Notification · Analytics
        ↑
Layer 5: 수익 부서 (Phase 3+)
  Advertising · Commerce
        ↑
Layer 6: 발현 채널 (Distribution)
  PWA (반응형 데스크탑+모바일) · 토스 미니앱 · 카카오 (가능성)
```

**핵심 원칙:** Layer 1~5가 사업 자체. Layer 6는 그 사업을 사용자에게 닿게 하는 방법. **채널이 망해도 위 5개 레이어가 살아 있으면 사업이 죽지 않는다.**

## 3. 비즈니스 캔버스 (9블록)

| 블록 | 내용 |
|------|------|
| 1. 고객 세그먼트 | 임신중 ~ 초등 자녀를 둔 한국 부모. **1차: 첫째 자녀, 정보 결핍 시점** |
| 2. 가치 명제 | 시기별 큐레이션 + 마감 트래커 + 한곳 모아보기 + 신청함/관심 체크리스트 |
| 3. 채널 | PWA (메인) · 토스 미니앱 (Phase 1.5) · 인스타 마케팅 (사용자 유입) |
| 4. 고객 관계 | 셀프 서비스 + 시기별 자동 알림 (Phase 2) |
| 5. 수익원 | ① 스폰서드 카드 ② 고정 배너 ③ 공구 수수료 ④ 브랜드 구독 |
| 6. 핵심 자원 | 큐레이션 DB · 사용자 행동 데이터 · 브랜드 관계 |
| 7. 핵심 활동 | 큐레이션 (수작업 → 자동수집+승인) · 운영 · 영업 |
| 8. 핵심 파트너 | 브랜드 (광고주) · 토스 · 사용자 제보자 |
| 9. 비용 구조 | Vercel·Supabase (~0원 시작) · 마케팅 · 본인 시간 |

가장 결정적인 셀: **6. 핵심 자원.** 사업의 진짜 자산은 큐레이션 DB의 *품질* 과 사용자 행동 *데이터*. 이 둘이 약하면 광고주 영업 무근거.

## 4. 부서 구조 (11개)

| # | 부서 | 역할 | 활성 시점 |
|---|------|------|----------|
| 1 | **Content** | 카드(모집/후기/공구/광고) 단일 진실원천 | Phase 1 ✅ |
| 2 | **Brand** | 브랜드·상품 정규화 | Phase 3 |
| 3 | **User** | 인증·프로필·아이 월령 | Phase 1 ✅ (OAuth 대기) |
| 4 | **Personalization** | 신청함/관심 체크 | Phase 1 ✅ (localStorage) |
| 5 | **Curation** | 상태 머신 + 승인 큐 | Phase 1 ✅ |
| 6 | **Discovery** | 검색·필터·정렬 | Phase 1 ✅ |
| 7 | **Ingestion** | 자동 수집 + 사용자 제보 | Phase 2 |
| 8 | **Notification** | 마감 D-1·신규 알림 | Phase 2 |
| 9 | **Analytics** | KPI·이벤트·퍼널·코호트 | **Phase 1 (지금)** |
| 10 | **Advertising** | 배너·인라인·고정 슬롯 | Phase 3 |
| 11 | **Commerce** | 공구·어필리에이트·구독 | Phase 4+ |

**왜 Monetization을 3개로 쪼개나:** 광고·공구·어필리에이트는 다른 시스템 (CPM 트래킹 vs 결제·배송 vs 외부 추적 코드). 한 부서로 두면 광고 코드 고치다 공구 망가짐.

**왜 Analytics를 Phase 1부터:** 측정하지 않은 것은 개선·증명 불가. 광고주 영업 시 "사용자 N명이 M% 행동한다"가 자료의 전부. Phase 3에 시작하면 그 전까지 데이터 0.

## 5. 검증 마일스톤 (M1~M6)

기존 Phase 1·2·3은 **기능 단위**. 사업 관점에선 **검증된 가설** 단위로 진척도를 측정해야 한다.

| 마일스톤 | 검증된 것 | 다음으로 갈 자격 |
|----------|----------|------------------|
| **M1 Validated Curiosity** | MAU > 100, 사람들이 들어와 카드를 본다 | 일단 살아 있음 |
| **M2 Validated Value** | 원문 클릭률 ≥ 15%, D7 재방문 ≥ 25% | 사용자가 실제로 가치를 느낌 |
| **M3 Validated Audience** | MAU ≥ 1,000, 자발적 추천(SNS·맘카페) 발생 | 광고주 대화 시작 자격 |
| **M4 Validated Revenue** | 첫 유료 광고주 1곳 결제 | 수익 모델 검증 |
| **M5 Validated Scale** | MAU ≥ 10,000, 월매출 ≥ 100만원 | 본업 전환 검토 |
| **M6 Validated Moat** | 경쟁자 등장에도 유지되는 차별점 (브랜드 관계·UGC·데이터) | 외부 투자·확장 검토 |

**현재 위치:** M1 직전. 코드는 있지만 사용자 데이터 0.

## 6. 검증해야 할 가설 (다섯 가지)

여기서 사업이 깨질 수 있는 지점들. 우선순위 순.

| # | 가설 | 깨지면 | 검증 방법 | 검증 시점 |
|---|------|--------|----------|-----------|
| 1 | 부모는 흩어진 협찬을 모아주면 시간 쓴다 | 사업 근본 부정 | MAU·재방문 (Analytics) | M1 직후 |
| 2 | 우리 시기/유형 분류가 직관적이다 | 필터 사용 안 함 → 가치 약화 | 필터 클릭 비율 + 사용자 인터뷰 5명 | 첫 100명 |
| 3 | 원문 클릭률 ≥ 15% | 광고 영업 무근거 | Analytics 이벤트 `source_link_click` | M1 1개월 후 |
| 4 | 브랜드가 우리에게 돈 낼 의향 있다 | 수익화 불가 | 5곳 영업 시도 (가설검증용) | M3 |
| 5 | 인스타 직접 검색보다 우리가 낫다 | 사용자 이탈 | 사용자 인터뷰 + 행동 데이터 | 초기부터 지속 |

가설 1·2·3은 무료(데이터만 필요). 4·5는 시간·노력 비용 있음.

## 7. 수익 예측 (현실적 범위)

> ⚠️ 전제: 트래픽이 없으면 모두 0. 본질은 "광고주가 우리 사용자 풀에 돈을 낼 만큼 가치 있게 보이느냐".

### Year 1 (Phase 1~2 · 큐레이션 미디어)
- MAU: 100~500 (현실) / 1,000~3,000 (낙관)
- 광고주 문의: 월 1~2건 (브랜드가 먼저 연락)
- **연 매출 예상: 0 ~ 500만원**
- 가장 가능성 높은 수익원: 평소 협찬받던 브랜드와 직접 약식 광고 (10~30만원/건)

### Year 2 (Phase 3 · 광고 본격화)
- MAU: 10,000~30,000 가정
- 월 페이지뷰: 50,000~200,000
- 디스플레이 광고 CPM (한국 모바일): 3,000~10,000원
- 스폰서드 카드: 월 3~5건 × 20~50만원
- **연 매출 예상: 300만 ~ 3,000만원**
- 부수입으로 의미 있는 수준

### Year 3+ (Phase 4 · 마켓플레이스)
- MAU: 50,000+
- 공구 거래액: 월 500만~2,000만 × 수수료 5% = 25~100만원
- 브랜드 구독: 5~10곳 × 30만원/월 = 150~300만원
- 디스플레이 광고 안정화
- **연 매출 예상: 3,000만 ~ 2억원**
- **1인 본업 전환 가능 구간** (월 250만원 기준선)

### 광고 슬롯 상품화 (Year 2~)

| 상품 | 위치 | 노출 보장 | 월 가격 (참고) |
|------|------|----------|----------------|
| 상단 고정 배너 | 메인 헤더 아래 | 100% (1주~1개월) | 200,000~1,000,000원 |
| 스폰서드 카드 | 그리드 1~3번째 자리 | 100% | 100,000~500,000원/주 |
| 인라인 광고 | 카드 사이 N번째 | CPM 기반 | 노출당 단가 |
| 상세 페이지 하단 | 카드 푸터 | 클릭당 | 100~500원/클릭 |
| 카테고리 스폰서 | "임신중" 필터 적용 시 상단 | 카테고리 도달 | 300,000원/월 |

### 1인 운영 viable point

| 월 매출 | 의미 |
|---------|------|
| 50만원 | 부수입으로 의미 있음 |
| 200만원 | 부업 → 본업 전환 고민 |
| 500만원+ | 1인 정식 사업, 외주·툴 투자 가능 |

### 위험 요인 (정직하게)
1. **트래픽이 가장 큰 변수** — MAU 1,000 이하면 광고주가 안 옴
2. **한국 출산율 감소** → 시장 자체가 -2~3%/년 축소 추세
3. **사용자가 우리 앱 우회** → 인스타 직접 보는 게 더 편하면 우리 가치 0
4. **경쟁사 흡수** — 멘토리가 외부 큐레이션 추가하면 차별점 약해짐
5. **광고 거부감** — 부모 사용자는 광고에 민감. 과다 노출 시 이탈

## 8. KPI 우선순위

**결정적 단일 KPI: 원문 클릭률 (`source_link_click` / 카드 상세 페이지뷰)**

이게 높으면:
- 사용자가 우리 큐레이션에 가치 느낀다 ✅
- 광고주에게 "우리 사용자는 행동한다" 증명 ✅
- 모든 수익 모델의 근거 ✅

이게 낮으면 (예: 5% 이하): 우리 앱은 "정보만 보고 안 움직이는 곳" → 광고주에게 팔 가치 없음.

### 매주 추적할 6대 지표

| 지표 | 정의 | 목표 (M2) |
|------|------|----------|
| **MAU** | 월 활성 사용자 | > 1,000 |
| **DAU/MAU** | 끈끈함 비율 | > 20% |
| **체크 전환율** | 카드 본 사람 중 "관심·신청함" 누른 % | > 30% |
| **원문 클릭률** | 상세 → 외부 인스타 이동 % | ≥ 15% |
| **재방문률** | D7 리텐션 | ≥ 25% |
| **카드당 노출수** | 카드별 view·click 카운트 | 카드별 차이 분석 |

## 11. 확정된 제약 (Constraints)

본인이 이미 결정해서 흔들리지 않는 항목들:

- **알림 방식: Web Push(앱푸시)만.** 이메일·SMS 알림 미사용. iOS에서 못 받는 사용자는 사이트 재방문 의존. → PWA 홈 화면 설치 유도가 더 중요해짐
- **앱 내 신청 처리 X (Phase 1~2).** 외부 인스타·블로그로 보내는 큐레이션 미디어 포지션 유지
- **인스타·틱톡 자동 크롤링 영구 금지.** 약관·법적 리스크
- **광고: 한 화면 최대 2개, 카테고리 매칭 필수, 의료·금융·사행성 거부**
- **자동 발행 절대 X.** 모든 외부 입력은 관리자 승인 게이트 통과
- **무료 티어 운영 우선.** 트래픽 검증 전엔 유료 전환 신중

## 10. 이 문서 활용법

- 새 기능 아이디어 → 6-Layer 어디에 들어가는지 확인. Layer 1~5 변경이면 큰 결정, Layer 6면 가벼움.
- 새 의사결정 → 미디어 정체성·페르소나·KPI 우선순위와 충돌 안 하는지 확인.
- 막힐 때 → "지금 마일스톤은 어디인가? 다음 마일스톤 가려면 뭘 해야 하나?" 한 줄로 자문.
