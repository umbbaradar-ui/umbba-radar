# 인스타 수집 파이프라인 — 최종 방향 (2026-06-21 확정)

> 이 문서가 새 수집 구조의 **단일 기준**. 이전: `DESIGN-OPTION-C-LOCAL-CLAUDE.md`(설계 경위), `WORKLOG-2026-06-20-BRIGHTDATA.md`(전환·비용 경위).

## 1. 왜 바꿨나 (두 가지 비용/리스크)
- **gallery-dl + 로그인 쿠키 → 401 계정밴**(쿨다운만 회복, 운영부담 큼)
- **유료 Vision API(Claude Sonnet)로 분류 → 비용 폭탄**(월 ₩25~50만, Gemini 키는 정지)
- **해결**: **BD 스캔(밴 없음)** + **로컬 Claude Code 분류(구독 정액 = 추가 $0)**

## 2. 핵심 원칙 — 수집과 분류를 분리
> "수집 = 데이터(이미지+캡션)를 DB에 쌓기. 분류 = 그 DB 데이터를 판단해 최종 카드로."
- 수집은 싸고 빠르게(AI 안 부름). 분류는 따로, 공짜(로컬 Claude)로.
- 분류는 **언제든 독립 실행** 가능 → 놓친 것 따라잡기 / 재분류 / 구독 한도 맞춰 분산.
- **이미지가 이미 DB에 있으면 재스크랩 불필요** → 분류는 순수 오프라인 변환.

## 3. 구조 (3단)
```
[1. 수집 루틴]  (맥 스케줄, 자주/싸게)
   BD discover 스캔 → 신규 글 → "미분류 카드"(이미지+캡션) DB 저장
     · 이미지: BD CDN → Supabase Storage (영구 저장, 만료 없음)
     · AI 안 부름. status=pending + 미분류 표시.

[2. 분류 루틴]  (맥 스케줄, 1번과 독립, 공짜)
   DB의 미분류 카드 읽기 → 로컬 헤드리스 Claude(구독 토큰) 분류
     · 진짜 모집 → 제목·카테고리·마감일 채워 "분류완료"
     · 노이즈 → 삭제(또는 archived)
     · RULES.md 그대로 적용. 배치+상한으로 구독 사용량 관리.

[3. 검수]  (운영자, 웹 /admin/queue)
   분류완료 카드 검수 → 발행
```

## 4. 비용 (확정)
| 항목 | 비용 |
|---|---|
| BD 스캔 | ~월 2.6만 (신규 글만 과금) |
| 분류(로컬 Claude) | **구독 정액 — 추가 $0** |
| Storage | keepers 이미지만 (노이즈는 분류 단계서 삭제) |
| **합계** | **~월 2.6만 + 구독(이미 보유)** |
- 유료 Vision API(Claude/Gemini) **안 씀.** 인스타 계정 부하 0. 서버 부하 가벼움.

## 5. 머신
- **24시간 켜두는 맥**에서 수집·분류 루틴 모두 `launchd` 스케줄.
- 코드는 크로스플랫폼(파이썬). 노트북/홈PC에서도 동일하게 돎.

## 6. 기존 "Vision 실패" junk 카드 처리
- 그것들 = **이미 이미지+캡션 있는 "미분류 카드"** → **분류 루틴이 그대로 흡수**(읽어서 확정 or 삭제).
- 재스크랩 X (이미지 Storage에 영구 저장됨, BD URL은 만료라 재스크랩이 오히려 손해).

## 7. 구현 상태 & 남은 일
**이미 됨**:
- BD 스캔·이미지·import 코드(`bd_client.py`, `bd_ingest.py`, `bd_local.py`)
- 로컬 헤드리스 Claude 분류 패턴(run-b.ps1 → `bd_local.py`에 이식)
- 마감일 연도 버그 수정·배포(`c7b1d71`)
- 맥 스케줄 스크립트(`bd-local.sh`, plist), 설계서

**남은 일** (이 방향 확정 시):
1. **수집측**: "Vision 안 부르고 미분류 카드 생성" 경로 (bulk-ingest에 skip-vision 플래그 or 전용 endpoint)
2. **분류측 서버 endpoint**: 미분류 카드 목록 / 분류결과로 카드 update / 노이즈 delete
3. **분류 루틴**: 미분류 카드 → 로컬 Claude → update/delete (bd_local의 Claude 호출부 재사용)
4. 기존 junk 일괄 분류(위 루틴 1회)
5. admin 현행화(대시보드 퍼널: 수집 큐 → "미분류→분류완료→발행"), 비용 표기 정정
6. 맥 이식 + launchd(수집·분류 2개 스케줄, 시각 분리)

**필요 결정/준비**:
- 로컬 Claude 분류 검증(맥, `claude setup-token`) — 마지막 미검증 관문
- 분류 루틴이 "미분류 카드"를 식별할 마커(현재 title `"(CLI 등록 — Vision 실패…)"` or 정식 status/flag 신설)
