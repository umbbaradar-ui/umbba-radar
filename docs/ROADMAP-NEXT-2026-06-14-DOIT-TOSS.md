## 0. 결론 먼저

1. **이미 정리돼 있었다** — `ROADMAP-NEXT.md`가 출시 후 방향을 우선순위까지 매긴 문서. 1·2순위(카드 공유버튼, 제보 강등·하단 3탭화)는 **완료**(커밋 aed3bdd).
2. **MAU0 관점 진단 — 부족한 건 신규 기능이 아니라 "이미 만든 걸 켜고 보이게" 하는 것.**
   - **(1) "오늘 또 들어올 이유"가 코드엔 다 있는데 화면에 안 보인다.** 자녀 시기 매칭(`stages.ts`·`getRecentMatchingCards`)·NEW 배지·마감 D-1 cron이 전부 구현돼 있는데, 홈 진입 순간 "오늘 너에게 새로 N건 떴어"라는 **daily loop 신호(가변 보상)가 시각화 안 됨**. 토스 혜택탭의 본질이 코드에 있는데 헤더 한 줄이 없어 매일 열 이유가 죽어있다.
   - **(2) 유일한 리텐션 무기(Web Push)가 꺼져 있다.** 이메일·SMS 영구금지(정책③)라 푸시가 **유일한** 복귀 채널인데, 파이프라인은 100% 구현돼 있고 **VAPID 키 미등록 하나 때문에 0% 가동** 중.
3. **"지금 1개만 한다면" → 푸시 VAPID 점화**(기존 로드맵 3순위). 공수 최소(키 1쌍 + env 2개), 효과 최대, 코드 0줄 수정.

> 콜드스타트(빈 커뮤니티)는 3순위 리스크다. 엄빠레이더는 "혼자 써도 가치 있는 큐레이션 미디어(single-player)"라 후기·방이 비어도 카드 자체가 유용 → **커뮤니티보다 daily loop 시각화 + 푸시 점화가 먼저**.

## 1. 레퍼런스에서 뽑은 것 (사실검증 통과분만)

### 1-A. 두잇(DoWit) — "함께 인증" 습관 앱
> 정확 대상: **두윗(DoWit, ㈜다이버즈, iOS "함께하는 운동 인증 챌린지")**. 동음이의 주의 — 배달앱 "두잇(Doeat)", 소셜매칭 "두윗"은 별개. 문서가 얇은 신생 앱이라 동일 카테고리 1위 **챌린저스**로 삼각검증.

핵심 = **행동을 눈에 보이는 증거로 남기고(인증) → 1탭 응원(상호성) → 또래가 하는 게 보임(사회적 증명)**. 기존 `user_post_status`(관심/신청함)를 거의 그대로 재활용해 이식 가능.

| 두잇 메커니즘 | 엄빠레이더 변형 | 전이도 |
|---|---|---|
| 사진/타임스탬프 인증 | **"신청했어요 → 받았어요" 2단계 토글** + "받았어요"에 선택적 한줄후기/별점 = 두잇 "사진 인증" 자리 | 高 |
| 함께 인증 + 실시간 현황 | **"같은 시기 엄빠들이 이번 주 많이 담은 TOP5"**(집계형, 게시판 X) | 高 |
| 1탭 응원·좋아요 | 후기·"받았어요"에 **♥/🎉/곰스티커 1탭 리액션**("곰이 응원중 ♥") | 高 |
| 스트릭·달성률 | "일 스트릭" 부적합 → **"주간 발견 스트릭"** 또는 "이번 달 3건 챌린지" | 中 |
| 개인화 리마인더 푸시 | = 로드맵 3순위 푸시(인프라 보유) | 高 |
| 콜드스타트: 프리빌트 방+시드 | **월령 방 미리 개설 + 관리자(곰)가 매일 카드 3선 시드** | 高 |
| 게이미피케이션 뱃지 | = 로드맵 4+ (첫 당첨🎉·후기5개✍·월령메이트 등) | 中 |
| 제보 UGC 선순환 | 제보 채택 시 제보자 뱃지+푸시 | 中 |

> ⚠️ **베끼지 말 것(검증됨)**: 챌린저스식 "돈 걸기·환급·랭킹 경쟁" → 사행성(정책⑤) 충돌. 보상은 **무보상 명예 뱃지/스트릭**(정책⑥)으로만.
> ⚠️ **인용 주의(검증됨)**: 두잇 "완주율 90%"는 자사 마케팅 수치·표본 불명. 두잇에 스트릭/뱃지/좋아요 UI가 실제 있는지는 미확정(스토어 문구로만 응원·실시간현황·성장히스토리·리마인더 확인). → **메커니즘 방향만 차용, 수치는 카피에 쓰지 말 것.**

### 1-B. 토스(Toss) — 비금융 관점(매일 열 이유·UX·바이럴·미니앱)
핵심 = **혜택탭("여기 오면 흩어진 혜택이 매일 새로 정리돼 있다") + 만보기/퀴즈의 "오늘 뭐 떴지" 가변 기대감**. 엄빠레이더 본질과 1:1 (외부 혜택 모아 외부로 트래픽 송출).

- **3-① Daily loop**: 토스 혜택탭 모델을 그대로 강화. "오늘 새로 스캔된 N건" + "○○이(개월수) 맞춤" 개인화 헤더. 만보기/퀴즈의 가변 기대를 **현금 대신 콘텐츠 자체로** 복제. **마감 카운트다운**(D-2/오늘 마감) = 협찬 마감은 진짜 손실이라 인공 스트릭보다 윤리적·강력.
- **3-② 토스 미니앱(앱인토스) 노출**: 이미 `umbba-radar-toss/` 존재 + "귀여운게 최고야" 챌린지 출품 예정. 토스가 홈/카테고리/검색/푸시로 입점앱에 유저를 흘려보냄 → **PWA·구글플레이보다 빠른 초기 유저 획득 경로 가설**. "임신/출산/육아/체험단" 키워드 등록 최적화.
- **3-③ 온보딩·UX "One page, One thing"**: 자녀 시기 **하나만** 입력 → 즉시 "12건 찾았어요" 아하 → 첫 "관심 ♥" 1탭. ViewGate 4장을 "랜덤→입력 시기 베스트 4장". 푸시 권한은 **절대 온보딩 첫 단계에서 묻지 않기**(high-intent 시점 prime-then-permission). 곰 1인칭 해요체.

> ⚠️ **불확실(검증됨)**: 토스 만보기 금액(현재 랜덤 평균 30~50원으로 축소), 앱인토스 유저 수치("9개월 2,053개·1.5개월 80만") = 토스 자기보고·독립검증 안 됨, "단일스텝 옵트인 3배"(PushEngage 자사·웹/모바일 맥락 상이) → **가설로 다루고 토스 콘솔 실유입·자체 A/B로 검증**.
> ⚠️ **친구초대 현금 리워드는 종료됨(과거형, 검증됨)** → 엄빠레이더는 애초에 현금형 부적합. **코호트/콘텐츠 바이럴**로 설계.

### 1-C. 한국 임신·육아 앱 — 리텐션 코어
베이비빌리·베이비타임·마미톡·차이의놀이·그로잉맘 공통 리텐션 코어 = **"자녀 시기(주수/개월령) 자동 동기화로 매일 바뀌는 콘텐츠 + 디데이/위젯 진척감 + 비슷한 시기 동기(同期) 그룹"**. 엄빠레이더는 이 "시기 동기화" 엔진을 이미 가진 `children`/`posts` 위에 그대로 얹을 수 있다.

- **시기 동기화 헤더**: 베이비빌리 "빌리 성장카드"·마미톡 280days처럼 "임신 28주·D-84 + 이 시기 한 줄"을 매일 갱신.
- **동기 그룹**(베이비빌리 "베동" = 출산예정월 자동 그룹핑, 검증됨): 풀 커뮤니티는 정책 부담 → **"같은 시기 TOP5" 집계형**으로 효용(또래 비교)만 추출.
- **디데이 위젯**: 앱 안 켜도 보이는 자리 점유. PWA 위젯 구현 가능성은 미검증 → 안 되면 **디데이 기반 Web Push**로 대체.

> ⚠️ 육아앱 누적회원 수치(베이비빌리 15만→200만 등 출처마다 상이, 베이비타임 "1억건", 마미톡 "No.1")는 전부 자사 마케팅·독립검증 안 됨(검증됨).

## 3. "지금 당장 1개만 한다면" → A. 푸시 VAPID 점화

**무엇**: `npx web-push generate-vapid-keys`로 키 생성 → Vercel env에 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY` 2개 등록 → 재배포. 그러면 `push-service.ts`·`PushToggle`·`notify-deadline` cron 전체가 **코드 0줄 수정으로 즉시 동작**.

**왜**:
1. **공수 대비 효과 최강** — 이미 80~90% 구현, 막힌 건 키 1쌍. 리텐션 엔진이 통째로 잠겨 있음.
2. **유일성** — 이메일·SMS 영구금지(③)라 푸시가 유일한 복귀 채널. MAU0에서 "처음 깐 사람 다시 데려오기"의 전부.
3. **이미 안전 설계됨** — cron이 "신규 매칭은 인앱만, 관심 카드 마감 D-1만 푸시"로 스팸 방지가 코드에 박혀 있어 권한 박탈 리스크 최소.

**단서**:
- VAPID 미설정 시 `PushToggle`이 빈 publicKey로 subscribe 시도 → 오류. 키 등록이 **버그 해소도 겸함**.
- 키만 켜고 **자동 발송 트리거를 공격적으로 늘리지 말 것**. 첫 단계는 "관심 카드 마감 D-1"(이미 구현)만. 신규 매칭 푸시는 옵트인·발송빈도 데이터 본 뒤.
- 옵트인 요청 시점을 high-intent(관심 첫 체크 직후·4번째 카드·원문클릭 직후)로 옮기는 prime 카드 1개만 같이.

**바로 그다음 1개 → B(오늘의 스캔 헤더).** A=다시 데려오는 손잡이(트리거), B=데려온 사람이 매일 볼 이유(가변보상). 둘이 daily loop를 완성. B도 `getRecentMatchingCards` 호출+헤더 한 줄이라 공수 소.

## 4. 코드 현황 — quick wins (적은 공수로 켜지는 것)

- **푸시(A)**: 파이프라인 100% 구현, **VAPID 키 2개 등록만** 하면 코드 0줄로 동작. cron `notify-deadline`(KST 09:00) 발송 로직까지 완비.
- **B2B 폼(E)**: `/business`에 입점·상품·제휴·인스타모니터링 4유형 폼 + `business_inquiries`(마이그레이션 019) + 더보기 시트 링크 **이미 완성** → 지금 바로 리드 수집 가능.
- **share_target(공유 수신)**: `manifest.ts` 등록 완료 → 인스타에서 "공유→엄빠레이더" 시 `/submit` 자동 prefill **이미 동작**. 안내 문구만 없음.
