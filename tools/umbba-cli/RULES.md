# 엄빠레이더 카드 분류 룰 (Claude Code 용)

이 문서는 너님(사용자)이 운영하면서 매일 다듬는 살아있는 룰셋이에요. Claude Code 는 이 룰을 따라 `todo-YYYYMMDD.json` 의 각 게시물을 분류합니다.

---

## 입력 / 출력 형식

**입력**: `/api/admin/queue/export-todo` 가 만든 JSON
```json
{
  "exported_at": "2026-05-28T12:00:00Z",
  "count": 50,
  "items": [
    {
      "queue_id": "uuid…",
      "url": "https://www.instagram.com/p/…/",
      "source_username": "bebero.kr",
      "source_post_date": "2026-05-27T08:28:55Z",
      "caption": "BEBBERO 후르츠 딸기 세미오버핏…"
    },
    ...
  ]
}
```

**출력**: `results.json` — Import endpoint 가 받는 형식
```json
{
  "items": [
    {
      "queue_id": "uuid…",          // 입력 그대로 (매칭용)
      "skip": false,                  // true 면 카드 생성 X (참고: 검수는 너 책임)
      "title": "후르츠 딸기 옷 증정",  // 브랜드명 X (별도 필드)
      "brand_name": "베베로",
      "body": "•이벤트 기간 : 5/27(수)-5/31(일)\n•참여방법\n- 베베로 팔로우\n- 댓글 + 친구 태그\n•증정: 후르츠 딸기 옷 SS 세트 (3명)\n•당첨자 발표 : 6/2(화) DM",  // 원문 그대로, 요약 X
      "search_keywords": "베이비옷,오버핏",
      "stage_categories": ["newborn", "infant"],
      "type_tags": ["experience", "form"],
      "topic": "parenting",
      "deadline": "2026-06-05T23:59:00+09:00",
      "confidence": 0.92
    }
  ]
}
```

## ⚠️ 검수는 Claude(너) 책임 — skip 적극 판단

**사용자는 노이즈 안 봄. 너(Claude)가 RULES.md 따라 명백한 노이즈는 무조건 skip 처리.**
모호하면 confidence 낮게 잡고 분류 시도. 진짜 안 떠오르면 그때만 skip.

### 필수 skip 패턴 (사용자 확인 X, 무조건 skip)

#### 1. 이벤트 기간 만료 ⏰
입력 JSON 의 `today_kst` 필드와 캡션의 마감일 비교:
- 캡션 "이벤트 기간 5/22~5/29" + today_kst = 2026-05-30 → **skip** ("이벤트 종료")
- 캡션 "마감 6/1까지" + today_kst = 2026-06-02 → **skip** ("마감 지남")
- 캡션 "선착순 30명" + 게시일이 today 보다 7일+ 전 + 마감 명시 없음 → **skip** ("선착순 마감 추정")
- `skip_reason: "이벤트 종료 (기간: X월 Y일~Z월 W일)"`

#### 2. 신청 방법 없음 = 모집 아님
캡션에 다음 패턴 **하나도 없으면** skip:
- "참여 방법", "신청", "응모", "모집", "댓글 + ...", "팔로우 + ..."
- "이벤트 종료 후 댓글 공지" 만 있고 응모 안내 X → skip
- `skip_reason: "신청 방법 없음 - 단순 광고/후기"`

#### 3. 단순 제품 광고·자랑
- "새 상품 출시", "리뉴얼 오픈" 같은 알림만
- 인플루언서 협찬 후기만 ("이거 정말 좋아요" 톤)
- `skip_reason: "단순 광고/협찬 후기"`

#### 4. 매장·서비스 영업 안내
- 매장 영업 시간 / 휴무 안내
- 새 매장 오픈 알림 (이벤트 X)
- `skip_reason: "매장 영업 안내"`

#### 5. 정책·기타 부적합
- 정치·종교·논란성
- 의료·금융·사행성 광고
- 너님 사이트 정책상 부적합 (예: 임상실험·다단계)
- `skip_reason: "정책상 부적합 - <구체>"`

#### 6. 무관한 다른 브랜드 콜라보 한 줄
- "다른 브랜드와 콜라보합니다" 만 있고 모집 X
- `skip_reason: "콜라보 알림만 - 모집 X"`

#### 7. LIVE 방송 안내 ⚠
- "오늘 9시 라이브", "LIVE 방송 진행" 같은 시청 안내
- 라이브는 모집·이벤트가 아니라 시청 권유 → skip
- 단, "라이브 시청 + 댓글 작성 시 추첨" 같은 명확한 응모는 분류 시도
- `skip_reason: "LIVE 방송 안내 - 시청 권유만"`

#### 8. 기존 구매자·사용자 대상 콘텐츠 모집 ⚠
- "○○로 만든 사진/영상 보내주세요"
- "○○ 사용하는 모습 담아주세요"
- "○○ 구매하신 분들 후기 모집"
- → 신규 사용자가 받을 게 없으므로 우리 사이트 사용자에 무관 → skip
- 단, "구매 안 한 분도 응모 가능" 명시되어 있으면 분류 시도
- `skip_reason: "기존 구매자 대상 콘텐츠 모집"`

#### 9. 같은 계정 내 동일 이벤트 중복 게시물 ⚠
같은 계정의 todo 항목 중 같은 이벤트를 여러 번 강조하는 패턴이 자주 있음:
- "전 피드 참조", "이전 글 참조"
- "어제 올린 이벤트 다시 안내드려요"
- 같은 캡션의 일부가 동일 + 같은 마감일
- → **가장 정보가 풍부한 것 1개만 분류**, 나머지는 skip
- `skip_reason: "@<username> 내 동일 이벤트 중복 (대표: queue_id <대표 id>)"`

분류 전 처리 순서:
1. JSON 의 모든 item 의 source_username 별로 묶어보기
2. 같은 계정의 게시물 중 캡션 키워드 (이벤트명·제품명·마감일) 비교
3. 동일 이벤트로 판단되면 가장 풍부한 1개만 살리고 나머지 skip

### 적극 분류 (skip 아닌 케이스)

캡션에 **하나라도** 있으면 카드 등록 시도 (confidence 낮아도):
- "댓글", "팔로우", "응모", "신청", "모집"
- "선착순", "추첨", "당첨"
- "체험단", "서포터즈", "키즈모델"
- "증정", "무료", "샘플"

→ confidence 0.5~0.7 정도로 분류해서 사용자가 카드 승인 단계에서 결정.

### 절대 사용자에게 묻지 마라
이전 RULES.md 의 "0.5 미만 → 사용자에게 물어봐" 룰은 **삭제**.
너님(Claude)이 판단하고 skip 또는 낮은 confidence 로 처리. 사용자 부담 ↓.

## body 작성 규칙 — **원문 그대로 (요약 금지)**

### ⚠️ 핵심: 요약하지 말고 원문 톤·구조 그대로
사용자(운영자)는 카드 상세에서 풍부한 정보 보길 원함. 짧게 요약하지 말고 캡션 원본의
필요한 섹션 그대로 옮기기. 줄바꿈·이모지·들여쓰기 일부 살려도 OK.

### 좋은 예
```
•이벤트 기간 : 5/27(수)-5/31(일)
•참여방법
- 마틸라 인스타그램 팔로우
- 가장 맘에 드는 컬러를 댓글로 작성
- 소개해주고 싶은 친구까지 태그하기!

*피드 순서대로 1.프레시룸 2.클래식룸 3.러브레터룸 4.사일런스룸

- 스토리 공유까지 함께하면 당첨확률 UP!
•당첨자 발표 : 6/2(화) (DM 안내)
```

### 나쁜 예 (요약)
```
"마틸라 셀루오실크 차렵이불 4컬러 중 마음에 드는 컬러 댓글+친구 태그.
팔로우 필수. 5명에게 SS 이불베개세트 증정. 발표 6/2 DM."
```
→ 정보 손실: 컬러 종류, 정확한 기간, 피드 순서 안내, 스토리 공유 보너스 등

### 포함할 정보 (있는 만큼 다)
- 이벤트 기간
- 참여 방법 (단계별)
- 증정 내용·인원
- 당첨자 발표 시기·방법
- 추가 조건 (스토리 공유 UP, 비공개 계정 제외 등)
- 제품 정보 (컬러·옵션 등)

### 글자 수
- 2000자까지 (DB 제한)
- 인스타 캡션이 그 안에 들어가면 거의 풀로
- 해시태그 (#가든데이즈 #이벤트 등) 만 제거 — 검색용 키워드 X, 카드 본문엔 노이즈

### 줄바꿈·서식
- 원본의 `•` `-` `*` 같은 불릿 표시 그대로
- 단락 사이 빈 줄 유지 (가독성)
- 너무 많은 이모지는 정리 (🌿🤍✨ 같은 장식성은 빼도 OK, 의미 있는 건 살림)

## stage_categories (시기 분류)

- `pregnancy`: 임신중 — 산모·임산부·예비맘·태교·산후조리원
- `newborn`: 신생아 0~3개월 — 신생아·산후·조리원·배냇·모빌·젖병(첫 단계)·분유(1단계)
- `infant`: 영아 4~12개월 — 이유식·기저귀·옹알이·뒤집기·앉기·치발기·범퍼침대
- `toddler`: 유아 1~7세 — 유치원·어린이집·식판·키즈카페·교구·동화책·배변훈련
- `elementary`: 초등생 8~13세 — 초등학교·학용품·방과후
- `all_ages`: 전연령 — 식기·청소기·가전·식품·살림 (시기 무관 가족 단위)

### 룰
- **이유식·젖꼭지·치발기·기저귀 키워드는 절대 all_ages 단독 X** → 해당 시기 명시
- 캡션에 "0~3개월", "백일 아기", "신생아용" 직접 표현 있으면 그대로
- 어른·가족 단위(공기청정기, 식기세트)일 때만 all_ages

### 안전 마진 룰 (애매하면 더 넓게)
사용자가 검색·필터 시 카드가 누락되지 않게, 적용 가능한 시기는 모두 포함:
- **베개·매트·잠자리 용품**: `newborn, infant, toddler` (신생아부터 사용)
- **선크림·자외선차단**: `infant, toddler, elementary` (영아부터 외출)
- **젖병·분유**: `newborn, infant` (둘 다)
- **이유식·식판·식기**: `infant, toddler`
- **장난감·교구**: 캡션의 대상 연령 따름 (없으면 `infant, toddler`)
- **모델 모집 (걷기 전·이전)**: `newborn, infant`
- **아동복**: 대상 시기 명확하면 그것만, 모호하면 `newborn, infant, toddler`

원칙: **너무 좁게 잡아 누락하는 것보다, 1~2 시기 더 넓게 잡는 게 낫다.**
단 `all_ages` 는 진짜 가족 단위 (공기청정기·청소기) 만.

## type_tags (복수 가능)

- `regram`: 본인 피드에 리그램(재게시) 필수
- `experience`: 체험단 — 제품 받고 후기·SNS 게시 의무
- `kids_model`: 키즈모델·아동 모델
- `supporters`: 서포터즈 — 장기 SNS 활동 (주 N회) 약속
- `form`: 별도 폼 작성 필수 (구글폼·네이버폼·카카오톡 채널 신청서)
  - 댓글·DM 만으로 신청 가능하면 form 아님
  - 다른 태그와 자유 조합 가능 (예: experience + form)

- `living`: 살림 (가전·가구·식기·청소·침구 — 가족 단위)

## deadline 추출 (캡션 본문 적극 탐색)

자주 나오는 패턴:
- "~까지", "마감: X월 Y일", "X월 Y일(요일) 자정", "X/Y 23:59"
- "선착순 N명 (~ 마감)"
- "이번 주 일요일까지" → 게시일 기준 가장 가까운 일요일 23:59 KST
- "오늘부터 7일간", "1주일간" → 게시일 + 해당 기간

ISO 8601 with +09:00 형식. 없으면 `null` (시스템이 자동으로 게시일 + 7일로 처리).

## search_keywords (검색 동의어, 콤마 구분 1~3개)

### ⚠️ 핵심: 제목·본문에 이미 있는 단어 절대 X
**제목·본문에 있는 단어를 또 search_keywords 에 넣으면 의미 없음.** (이미 검색되니까)
search_keywords 의 목적은 사용자가 **다른 표현으로 검색했을 때도 카드가 잡히게** 하는 것.

### 좋은 예 (동의어·유사어·상위어)
| 본문 | search_keywords |
|---|---|
| "신생아 젖병 2종 증정" | "수유용품,분유병" |
| "허그곰 쿨링 베개" | "유아베개,쿨매트,잠자리" |

## confidence (0.0 ~ 1.0)

분류에 얼마나 자신 있는지. 사용자 검수 우선순위 결정용.

### 기본 점수 = 0.85 에서 시작 → 가감

**+0.05 ~ +0.10 (자신감 ↑)**
- 캡션에 제품명·이벤트 형식 명시적
- 마감일 정확히 표기 (예: "5/31 까지")
- 시기 단서 직접 표현 ("100일 아기", "0~3개월")
- 키즈모델·서포터즈처럼 형식 명확

**-0.05 ~ -0.15 (자신감 ↓)**
- 캡션이 200자 미만으로 짧음
- 마감일 추정 ("이번 주", "곧" 등 모호)
- 시기 단서 없어서 추정
- 캡션 잘림 (`✔️` 끝, `...` 끝)
- 모집 vs 단순 광고 헷갈림

### 범위 의미
- **0.90~1.00**: 거의 확실, 검수에서 빠른 발행
- **0.75~0.89**: 일반적, 검수에서 한 번 확인
- **0.60~0.74**: 단서 부족, 검수 시 제목·시기 수정 가능성 있음
- **0.50~0.59**: 모호, 사용자가 카드 발행 결정
- **0.50 미만**: **명백 노이즈면 skip 으로** / 그게 아니면 0.50 으로 보내고 사용자 결정

### 결과 일관성을 위해
같은 캡션을 다른 세션에서 분류해도 ±0.05 안에서 결과 나오게 위 기준 엄격히 따르기.

### ❌ 사용자 확인 요청 X
이전 룰의 "0.5 미만 → 사용자에게 물어봐" 패턴은 **사용**. 사용자는 너님이 만든 결과만 검토하고 발행 결정. 너님이 대화 도중 멈추고 묻지 마세요.
